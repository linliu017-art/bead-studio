# 图片转拼豆关卡试验复盘

2026 年 11 月 11 日。样本是「草莓牛奶盒」的像素参考稿，以及用户提供的「星星小虎」JPG 插画。产品和工程约束见 [首版产品需求 v0.2](首版产品需求.md) 和 [开发规格 v0.2](开发规格.md)。

## 试验结果

| 输入和处理 | 输出 | 实际验证 |
| --- | --- | --- |
| 草莓牛奶盒像素参考稿 → Perler → 编辑记录 JSON → 项目色板 | 32×32、500 颗、9 色 | 网页棋盘放豆与刷新恢复成功。像素稿已有清晰边线和少量颜色，转换负担较小 |
| 小虎 JPG 直接导入 Perler，保留背景 | 38×48、1,786 颗、8 色 | 浅色背景也变成要放的豆子 |
| 同一 JPG 启用自动去白底 | 38×48、749 颗、8 色 | 外部背景消失，白云、肚皮等主体白色也被挖空 |
| 根据原图找回主体白色 | 38×48、1,037 颗、9 色 | 网页棋盘可放豆与存档，笑嘴、星尖和部分轮廓仍有明显损失 |
| 紧裁构图、强化轮廓、简化色板并逐格修细节 | 初修 46×48、1,461 颗、6 色。经星形、云脸和杖身迭代，定稿 46×48、1,441 颗、6 色 | 初修版在 Cocos 放豆、存档并加载完成态。定稿版通过图纸细节、放豆和熨烫逻辑验证，成品由游戏同一渲染函数生成 |

小虎定稿说明图纸能作为游戏数据使用。试验同时保留了直接转换的结果。可发布的图案质量和实际制作时长仍需按用途验收，特别是小虎的豆数超过首版中后期建议的 500～800 颗。

## 问题、原因和以后怎么检查

| 遇到的问题 | 原因 | 固化到制关流程的处理 |
| --- | --- | --- |
| 生成宽度设为 32，编辑器最初仍导出 52×52 的画布 | Perler 的生成宽度与编辑画布独立。项目单边上限是 48 | 预览和校验读取导出数据的真实宽高。保留原图比例，先裁构图，发现超限就提示重选尺寸 |
| 白底变成大量豆子，去白底后又丢掉白云和肚皮 | 仅按浅色判断背景无法区分底色与主体留白，封闭白区还可能和真正的镂空同色 | 从边界追踪可去除背景，预览可切换保留背景并支持局部恢复。透明 PNG 优先保留原有透明信息 |
| 原图能看出笑眼、笑嘴和星形，缩成小棋盘后失去辨识度 | 原图留白占用格数。细线、短笔画与小凹口进入混色格后被面积更大的颜色吞掉 | 裁主体、按格采样并给深色轮廓适当优先级。对照原图做成品尺寸和局部放大两次审查 |
| 星形像十字，魔杖星看起来缺一块 | 分辨率不足，黑边和填色挤在一起。局部避让虎耳时削掉星角体积。先前只标了尖角和留白，未覆盖尖角内侧 | 校验五个尖角、凹口和内侧填色，同时核对整圈闭合。只对参照原图标过的部位应用这些要求 |
| 云朵右眼与腮红粘连，笑嘴角接处看着断开 | 量化把不同部件落到斜角相邻的格子上。连通性对识别粘连与对笔画连续性的要求不同 | 分别标眼、嘴和腮红。不同部件之间检查斜角接触，笑嘴等连续笔画检查格边相连 |
| 魔杖与星星已经相接，接缝仍像突然拐成黑横线 | 棕色杖身提前一格结束，深色外沿把意图遮住。轮廓连通检查本身无法验证内部材质延续 | 轮廓和内部色带分别标注。对重要接缝同时核对位置、方向和色带是否延续 |
| 源工具可导出编辑记录，游戏仍无法直接使用 | 上游以字符串色号和空值表达格子。游戏使用数字色号、空格 `0`，并要求关卡 ID、主题、序号和版本 | 建立显式映射。保留目标数据与图纸版本，输出前检查色板、尺寸、空图和格子索引 |
| 图纸能加载，实际拼豆可能太久 | 豆数和色数只解释部分难度，大片同色、散点密度、相近色和缩放都会影响制作 | 预览显示尺寸、豆数、色数。用产品现有难度目标和手机试玩定关卡归属 |

## 验收留下的材料

- Perler 的编辑记录和原图对照能保留每格来源，适合追踪转换参数和人工修格。
- 关卡 JSON 是 Cocos 游戏的目标数据。修格后递增 `revision`，旧格子坐标的存档不能直接套到新图上。
- 细节标注由制关者参照原图填写。现有检查能发现已标注的缺格、粘连、断点和轮廓漏口。构图、辨识度与手感由预览和试玩覆盖。
- 试验曾用独立本机地址提供草稿数据，验证现有玩法能承接它。正式接入建议走项目的开发试玩入口，方案见 [图片转关卡接入规格](../SPEC-image-to-level.md)。

# 微信拼豆闯关游戏首版产品需求

版本 v0.2 · 2026 年 10 月 17 日 · 状态为需求草稿

面向希望通过手机完成像素手工作品的玩家，首版提供顺序闯关、拼豆、熨烫和作品收藏。第一关即呈现有轮廓、阴影和装饰细节的完整作品，让玩家愿意完成并保存成品。

## 已确认方向与设计假设

用户已确认采用微信小游戏方向，以个人身份准备账号；首版采用通关模式，自由创作放到第二版。首版作品不能过度简单，采用精致像素手作方向。操作页已确认采用奶油白底色、浅暖粉棋盘、草莓红强调和鲜艳豆子；已删除缩小、放大、复位和移动四个按钮，保留双指手势及找一找。

以下为本稿的落地建议，原型测试后调整：竖屏、2D 立体豆子效果、20 关、两个收藏主题、正确颜色落豆、无倒计时与生命值、本地存档。技术路线沿用 Cocos Creator 与 TypeScript；本稿不展开工程实现。

参考视频尚未成功读取，玩法和画面依据本次讨论定义，不作为视频复刻规格。个人主体的注册、类目和正式上线条件需在微信后台实际核对，不影响本地玩法验证。

## 产品目标

玩家能够在零散时间完成一件有细节的作品，随时中断和继续，并通过作品集看到自己的积累。

初轮验证重点是玩家能否自行理解操作、放豆是否顺畅，以及完成后是否愿意继续。当前没有用户行为基线，不承诺留存或商业收益。

| 观察项 | 口径与验证方式 |
| --- | --- |
| 教学理解 | 观察首次玩家是否能在开头引导后独立选色、放豆和换色；记录需要解释的位置 |
| 关卡完成 | 记录进入关卡、正确放下第一颗豆、开始熨烫和领取成品的时间与中断点 |
| 下一关意愿 | 完成首关后，不催促玩家，观察是否主动开始下一关，并记录原因 |
| 操作负担 | 记录漏格、误触、频繁寻找剩余位置和因手指遮挡产生的停顿 |
| 关卡时长 | 统计主动操作时间，排除切后台时间；与下方设计目标对照，不作为通关门槛 |

首轮建议邀请 5～8 名首次玩家做方向性测试，不将小样本结果当作稳定比例。

| 功能 | 优先级 | 首版要求 |

## 作品和关卡设计

有效豆数指作品中实际需要放置的豆子数量，空白孔位不计入。难度同时考虑有效豆数、颜色数、零散色块数量、相似颜色和空间分布；不能仅通过扩大棋盘增加难度。

下表为制作目标。实际图纸需要逐张统计豆数和色数，再根据试玩调整时长。早期图案可按构图选择 24×24、28×28 或 32×32 底板。现有草莓蛋糕原型为 28×28、334 个有效位置、7 色，作为工程迁移与试玩样本保留，超过早期建议豆数的部分通过实际时长验证。

| 关卡阶段 | 有效豆数目标 | 颜色数目标 | 主动操作时长目标 | 体验 |
| --- | --- | --- | --- | --- |
| 第 1～3 关 | 180～300 | 5～7 | 3～5 分钟 | 完整小作品，大块色面与少量细节相结合 |
| 第 4～10 关 | 300～500 | 7～10 | 5～8 分钟 | 增加阴影、配件和零散点缀，中途安排一张舒缓关 |
| 第 11～20 关 | 500～800 | 10～14 | 8～12 分钟 | 多个构成部分，支持放大完成与区域进度反馈 |

## 页面与完整流程

首页包含继续拼豆、关卡列表、作品集和设置。首次进入时直接突出第 1 关，不要求登录或填写昵称。

关卡列表显示预览、关卡编号、未解锁、进行中和已完成状态。锁定关卡可以查看预览，不能开始；不得以分享或广告作为解锁条件。

游戏页上方显示关卡名、总体进度和返回入口；中间为棋盘；下方为色板与当前颜色剩余豆数。提示和设置放在不遮挡作品的位置，缩放与平移使用双指手势，不提供独立缩放、复位或移动按钮。

玩家拼完后进入熨烫，再揭纸领取成品。成品页展示作品名、收藏结果、下一关和查看作品集。最后一关完成后进入主题完成页，仍可返回重玩。

作品集显示全部收藏位置，未获得作品使用轮廓预览；已获得作品可打开查看。首版使用统一展架样式，主题全部完成后给予整架完成反馈，不另建奖励经济系统。

## 拼豆操作规则

### 首关教学

第一关从完整草莓蛋糕图案开始。用短提示引导选择颜色、点击放豆，再滑动完成一小块奶油区域；随后恢复完整操作。教学不要求先完成一张单独的简单图。

用过的提示自动关闭，不反复打断。玩家在完成教学前退出时，保留作品；回来只提示尚未掌握的操作。双指缩放在需要时轻提示一次，不强制进入教学关。

### 放豆与换色

- 选色后，对应未完成孔位显示浅色提示；其他颜色降低亮度，但轮廓仍可辨认。
- 单击正确空位放一颗豆。单指滑动连续放置，快速移动也应覆盖路径经过的有效格子。
- 错色位置、作品外空白和已有豆子的位置不产生落豆，不扣分、不播放重复成功反馈。
- 不提供整片自动填充。连续放置仍要求手指经过各孔位，保留制作过程。
- 当前颜色完成后显示勾选，提示下一种未完成颜色，由玩家点选切换；颜色盒位置保持稳定。
- 首版不允许错色落豆，因此不需要专门的橡皮和纠错撤销。重新开始当前作品在菜单中提供，并明确确认清空后果。

总体进度按正确已放豆数除以有效目标豆数计算。只有全部目标孔位完成才进入熨烫，不能因百分比四舍五入显示 100% 而提前通关。

### 缩放和遮挡

单指负责放豆，双指负责缩放和移动。第二根手指出现时停止落豆，直至手势结束，不在缩放途中补放豆子。缩放以双指中心附近为基准，缩回最小倍率时回到完整作品。找一找自动放大并移到一颗未完成豆子，用持续闪动描边和箭头标记，填好后消失；再次点击依次找下一颗。优先当前颜色，当前色完成时切到其他未完成颜色，提示不自动填豆。

放大后可显示手指上方的孔位预览，避免遮住落点。该预览是否常驻由真机试玩决定。相邻颜色不能只依赖色相辨认，色板同时提供编号或简短标签。

### 大图区域进度

中后期作品可按构图划为 2～4 个区域，展示各区完成状态。区域用于进度反馈和快速定位，不强制锁定制作顺序；玩家仍可在整张棋盘上自由选择正确孔位。

区域完成时用短动画提示，不弹出必须关闭的窗口。全图完成后统一熨烫，不重复要求每区熨烫。

## 熨烫和领取成品

拼豆完成后锁定放豆操作，显示烘焙纸与熨斗。玩家拖动熨斗覆盖作品，经过的区域逐渐呈现融合质感；不能只在一个角落反复移动就完成整图。

覆盖完成后显示揭纸入口，执行一次短拖动揭纸；同时提供点击揭开方式。整个环节以约 8～15 秒为初步目标，试玩后调整。完成后脱板展示成品，豆子形态变化仍保留拼豆辨识度。

全部加热覆盖是熨烫完成条件。领取成品后保存通关状态、解锁下一关并加入作品集。重复进入领取页不重复创建收藏；已完成关重玩也不清除原通关记录。

熨烫中退出时保存加热进度；已完成熨烫但尚未领取时，回来进入待领取状态。揭纸动画允许重新播放，不影响通关结果的一致性。

## 存档与异常处理

| 情况 | 行为与恢复 |
| --- | --- |
| 主动返回或切后台 | 保存已完成操作与所处阶段，回来继续该阶段 |
| 快速放豆期间中断 | 本地保存已确认的格子变化；具体持久化频率由工程规格确定并通过强制退出测试 |
| 存储失败 | 明确提示进度保存失败，可重试，不声称已保存成功 |
| 单关存档无法读取 | 保留其他关卡和通关记录，提示当前作品需重新开始，不静默清空全部数据 |
| 重玩已完成关 | 使用独立本次进度；原收藏和后续解锁保留 |
| 点击重新开始 | 说明会清空当前制作进度，确认后才执行；已领取收藏不删除 |
| 关卡资源读取失败 | 展示重试入口，不能进入缺失目标图案的棋盘 |
| 拒绝图片保存权限 | 保持成品页可用，不影响收藏或下一关 |
| 无网络 | 在所需关卡资源已具备时可继续制作；不能笼统承诺未下载关卡也可用 |

验证版仅保存于当前设备，本地数据被微信清理或删除后不能保证恢复，不展示跨设备同步能力。

## 验收与观察记录

以下为交付前需验证的条件，目前尚未执行测试。使用至少一台 iPhone 和一台 Android 真机，记录具体型号、系统和微信版本，覆盖实际选定的支持范围。

| 场景 | 通过条件 |
| --- | --- |
| 初始进入 | 第 1 关可开始，其他关状态正确，无登录阻塞 |
| 正确与错误落点 | 正确位置落一颗，错误或重复位置不改变作品和进度 |
| 快速滑动 | 路径穿过的正确孔位连续落豆，重复经过不重复计数 |
| 双指操作 | 缩放和平移期间不误放豆；变换后孔位选择准确 |
| 颜色完成 | 已完成状态与剩余数量一致，颜色盒不跳位 |
| 通关判定 | 最后一颗目标豆放下后才能熨烫，无提前或无法完成的情况 |
| 熨烫与揭纸 | 必须覆盖有效作品区域；揭纸可操作，领取结果正确 |
| 中断恢复 | 拼豆中、熨烫中、待领取和领取后分别退出重进，恢复正确阶段 |
| 解锁与重复操作 | 领取后只解锁正确的下一关，重复领取不重复收藏，重玩不回退解锁 |
| 最复杂样本 | 甜品店橱窗连续操作无明显卡顿，放大后豆子清晰、按钮可用 |
| 作品集 | 收藏与通关对应，主题完成反馈正确，锁定与获得状态易区分 |

试玩记录关卡、设备、进入和完成阶段、主动操作时长、中断原因、是否继续下一关。原型阶段可人工观察和记录，首版数据采集方案另行确定，避免采集无关个人信息。

## 开发交接边界与第二版

下一份工程规格需要定义棋盘坐标和手势处理、关卡格式及校验、存档恢复、资源管理、微信能力适配和性能验证。作品目标数据与玩家状态分开，使第二版自由创作能复用棋盘和豆子表现。

第二版再考虑空白画布、自由选色、擦除撤销、自定义作品保存和编辑；照片转图纸、云同步与商业化分别评估，不默认为第二版必做。

画面风格以已确认的操作页为准；正式美术仍需细化其他页面布局和确定游戏名称。注册与正式发布相关要求在微信后台核对，首轮可玩验证无需等待账号全部手续完成。
